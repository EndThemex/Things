# 看板页面优化：丰富数据类型与组件

## Context

看板页（`apps/web/src/pages/Dashboard.tsx`）目前只有 3 个概览卡片、分类数量分布 Donut、数量最少 Top10、最近修改四个区块；后端 `/api/stats/overview` 返回的 `tagDistribution` 前端未展示，`stock_movements`、`plans` 等数据源完全未利用。本次优化在**不引入任何新依赖**的前提下（图表全部手写 SVG / HTML，已与用户确认），扩充概览指标并新增 4 类模块：出入库趋势与动态、库存价值分析、标签分布、方案概览。

## 改动文件与顺序

| 顺序 | 文件 | 改动 |
|---|---|---|
| 1 | `apps/server/src/routes/stats.ts` | `/overview` 新增统计字段（见下） |
| 2 | `apps/web/src/types.ts` | 扩展 `StatsOverview` 类型 |
| 3 | `apps/web/src/components/FeasibleBadge.tsx`（新建）+ `apps/web/src/pages/Plans.tsx` | 从 Plans.tsx 抽出 FeasibleBadge 为独立组件，Plans.tsx 改为 import |
| 4 | `apps/web/src/pages/Dashboard.tsx` | 概览卡 3→6、新增图表与列表区块、Row/Col 重排 |

无需数据库迁移、无需新依赖、无需新单测（看板属展示层；现有 `services/*.test.ts` 不受影响）。

## 1. 后端 stats.ts 新增字段

所有查询沿用现有风格：过滤 `isNull(components.deletedAt)`、camelCase 命名、金额 `round2(x).toFixed(2)` 字符串、排序在 JS 做。import 需补 `and, gt, gte` 与 `stockMovements`。

- **summary 扩充**：`categoryCount`（categories 表全量 count）、`zeroStock`（`quantity = 0` 的物品数，卡片标题「零库存」）。
- **categoryValueDistribution**：leftJoin categories，`groupBy components.categoryId`，`value = coalesce(sum(quantity * cast(price as real)), 0)`，JS 端 `round2().toFixed(2)` 并按 value 降序；`name ?? "未分类"`。注意 price 为 TEXT 可空，必须 coalesce。
- **valueTop10**：leftJoin categories，`value = coalesce(quantity * cast(price as real), 0)`，where `value > 0`，orderBy value desc, name asc，limit 10；返回 id/name/categoryName/quantity/price/imagePath/value(字符串)。
- **movementTrend（近 14 天）**：从 stockMovements innerJoin components（过滤回收站），按 `date(created_at, '+8 hours')` 分组（Asia/Shanghai 固定 UTC+8，规避 UTC 日期偏差；加中文注释），聚合 `inbound = sum(case when delta>0 then delta else 0 end)`、`outbound = sum(case when delta<0 then -delta else 0 end)`；截止点由 JS 按本地日期算 13 天前的本地零点转 ISO（**勿用 toISOString().slice(0,10) 生成日期清单**，需本地 pad 生成 YYYY-MM-DD）；返回固定 14 项，缺失日期补 `{date, inbound:0, outbound:0}`。
- **recentMovements**：stockMovements innerJoin components（过滤回收站），`orderBy desc(stockMovements.id)` limit 10，返回 id/componentId/componentName/delta/reason/createdAt。

## 2. types.ts 扩展 StatsOverview

沿用现有模式：`Card size="small"`、`Row/Col gutter=12`、`Flex gap=12`、`Empty PRESENTED_IMAGE_SIMPLE` 空态、`theme.useToken()` 着色、`Link` 跳转、`PALETTE` 色板。

新增组件（均定义在 Dashboard.tsx 内，与 Donut 同级）：

- **TrendBars（手写 SVG 分组柱状图）**：`viewBox` 固定 + `width="100%"` 等比缩放；每天两根并列入柱（入库 `token.colorSuccess`、出库 `token.colorError`），基线 + 2~3 条网格线与刻度文字，每柱包 `<title>` 原生悬浮提示，x 轴偶数位显示 `MM-DD` 防重叠；全零时不显 Empty，图下一行 secondary 文字「近 14 天无出入库记录」；图上方 Flex 图例（入/出色点）。
- **分类价值分布**：纯 HTML 进度行（与现有「数量最少 Top10」同构：色点 + 名称 ellipsis + 条 + ¥金额 flexShrink:0）。**颜色必须按 categoryId 复用 categoryDistribution 的取色 Map**，保证两图同分类同色；条宽 = value/maxValue。整行 Link `/components?categoryId=x&sort=quantity_desc`（未分类跳 `/components`）。
- **价值最高 Top10**：同构进度行，次行小字 `categoryName · ×quantity · 单价`；整行 Link `/components?q=名称`。
- **标签分布**：`Flex wrap gap=8` 内 AntD `Tag`（名称 + 加粗计数），外层 Link `/components?tagIds=${id}`（Components.tsx 已支持该参数并高亮）。空态 Empty。
- **最近出入库流水**：与「最近修改」同构行；delta 显示 `Tag color={delta>0?"success":"error"}`（`+N` / `N`）、reason ellipsis、右侧 `formatTime`；整行 Link `/components?q=名称`。
- **方案概览卡**：独立 `useQuery({ queryKey: ["plans"], queryFn: () => api<{items: PlanSummary[]}>("/plans") })`（与 Plans.tsx 同 key 共享缓存）。顶部 mini 指标：方案数 / 缺料数（>0 红色）/ 可行数；列表最多 5 条（缺料的排前），每行 Link `/plans/:id` = 方案名 + FeasibleBadge + 缺料 N；底部「查看全部方案 →」Link `/plans`；空态 Empty。

## 风险点

- **时区分组**：趋势按 `date(created_at, '+8 hours')` 分组，日期清单在 JS 按本地日期生成（勿用 toISOString 截日期）；若 SQLite `date()` 对带 Z 的 ISO 串解析异常，退化为拉原始行在 JS 分组。
- **price TEXT 脏值**：null/空串经 coalesce 归 0，金额统一 round2 后 toFixed(2)。
- **空数据**：无流水/无标签/无方案/无计价物品四类空态均需覆盖。
- **回收站**：趋势与流水 innerJoin 过滤 deletedAt，保证行内链接跳转不落空。
